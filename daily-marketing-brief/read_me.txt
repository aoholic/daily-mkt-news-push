================================================================================
每日营销简报 Skill 使用指南
daily-marketing-brief
================================================================================

【这是什么】

把「每日广告营销行业资讯简报」的完整工作流打包成一个可移植的技能包。
装到任何一台装了 WorkBuddy 的设备上，那台设备就能按同一套标准跑简报：
同样的信源清单、同样的去重规则、同样的三档分级、同样的排版格式。

原来这些信息分散在定时任务的 prompt 和历史执行记忆里，换台设备就没了。
现在它们都固化在文件里，跟着技能包一起走。


================================================================================
一、安装（3 步）
================================================================================

第 1 步：解压
    把 daily-marketing-brief.zip 解压，得到 daily-marketing-brief 文件夹。

第 2 步：放到技能目录
    Windows    : C:\Users\<你的用户名>\.workbuddy\skills\
    macOS/Linux: ~/.workbuddy/skills/

    放好之后的路径应该是：
        ~/.workbuddy/skills/daily-marketing-brief/SKILL.md

    注意：文件夹名字必须是 daily-marketing-brief，不要改名，
    也不要多套一层目录（不要出现 skills/daily-marketing-brief/daily-marketing-brief/）。

第 3 步：建简报存放目录
    在你打算用的工作目录下建一个「营销简报」文件夹：
        <工作目录>/营销简报/

    例如：
        C:\Users\Vera\WorkBuddy\广告营销行业\营销简报\

    所有简报都会写成这个目录下的「每日营销简报_YYYYMMDD.md」。

    提示：如果多台设备共用这个技能，把这个目录放在同步盘（OneDrive、云盘等）
    里，各设备的去重历史才能共享，否则两台机器会各自去重、产出重复内容。

不需要重启，也不需要额外配置。装好即可用。


================================================================================
二、怎么用
================================================================================

【方式 A：手动生成（推荐先试一次）】

    直接在对话里说：
        "今天的营销简报"
        "跑一下日报"
        "生成 2026年10月21日 的营销简报"

    WorkBuddy 会自动匹配到本技能并按流程执行。

【方式 B：挂到定时任务（推荐长期用）】

    在新设备上创建一个定时任务，参数照抄：

        名称        : 每日营销简报
        类型        : recurring（重复）
        执行时间    : 每天 09:00
        工作目录    : 该设备上的工作目录绝对路径
        任务内容    : 见下方【定时任务 prompt】

    【定时任务 prompt】（复制这段，把 <工作目录> 换成实际路径）

        执行「每日营销简报」：使用 daily-marketing-brief 技能，按技能中
        定义的流程生成本日广告营销行业资讯简报。

        要求：
        1. 先用 scripts/check_workday.py 判断是否触发——非中国大陆法定
           工作日（含调休）则不推送，直接说明原因后结束。
        2. 简报目录：<工作目录>/营销简报/，文件名 每日营销简报_YYYYMMDD.md。
        3. 严格按技能定义的信源清单、去重规则、三档分级与产出模板执行。
        4. 产出完整 .md 文件后，按技能中的推送消息格式在对话中直接发给
           主人，并附上文件路径。

    【为什么用"每天"而不是"工作日"】
    调休补班经常落在周六周日。如果把定时规则限定成周一到周五，补班那天
    会漏跑。所以保持"每天触发"，由脚本自己判断是否真的工作日——周末空跑
    的代价只是一次判断，不会产生多余文件。


================================================================================
三、它每一步在做什么
================================================================================

第 0 步  判断今天是不是中国大陆法定工作日。不是就直接结束，不抓不写。
第 1 步  找到上一个工作日的简报文件，作为去重基准，确定本期覆盖周期。
第 2 步  按 13 个核心站点 + 12 个公众号 + 补充信源逐个抓取最新资讯。
第 3 步  与历史简报逐条比对，同事件无新增就丢掉；有实质新增标注【更新】。
第 4 步  按重要性分三档：红（重大动态/政策/平台大动作）、黄（趋势/案例/
         数据）、绿（常规资讯/活动预告/代言联名）。
第 5 步  生成完整的 .md 简报文件（行事历、分级条目、数据速览、趋势研判、
         重点信号）。
第 6 步  在对话里直接给出精简推送版，可直接复制转发。


================================================================================
四、文件夹里都有什么
================================================================================

daily-marketing-brief/
│
├── SKILL.md                      主流程。WorkBuddy 每次运行时读的就是它。
│                                 想改流程、改口吻、改称呼，改这个文件。
│
├── read_me.txt                   本文件（人类阅读用，不影响运行）
│
├── references/
│   ├── sources.md                信源清单：13 个站点、12 个公众号、补充信源，
│   │                             以及每个源的抓取手法和已知坑。
│   │                             想增删信源，改这个文件。
│   │
│   ├── output-template.md        简报 .md 的结构模板 + 推送消息模板。
│   │                             想改排版、改推送格式，改这个文件。
│   │
│   └── automation-setup.md       异地复刻定时任务的完整说明，含多设备去重、
│                                 云端化的三个改造项。
│
├── scripts/
│   └── check_workday.py          工作日 / 节假日 / 调休判定脚本。
│                                 【需要每年维护一次，见第五节】
│
└── assets/
    └── sample-brief.md           2026年10月21日那期成品，作为格式基准。
                                  想改风格，换掉这个样例文件即可。


================================================================================
五、每年要做的一次维护
================================================================================

scripts/check_workday.py 里有两个空表：

    HOLIDAYS            法定节假日（不工作的日子）
    WORKDAY_OVERRIDES   调休补班（本该休息但要上班的日子）

国务院办公厅一般在每年 10-11 月发布次年的放假安排。拿到之后，把日期按
注释里的格式填进这两个表。

没填之前会怎样？
    脚本退化成"周一到周五就触发，周末就跳过"。平时没问题，但遇到调休
    （比如某个周日要补班）会误判成跳过。

怎么填？
    直接编辑文件，或者把放假安排丢给 WorkBuddy，说"把这个填进
    check_workday.py 的节假日表"，它会自己填。


================================================================================
六、常见问题
================================================================================

Q：微信能自动收到吗？
A：不能。目前没有可用的微信直发通道。技能会在对话里给出排版好的精简版
   文字，你复制转发即可。这是已知限制，不是配置问题。

Q：新设备没有历史简报，第一期会不会有问题？
A：不会。找不到历史文件时就跳过去重，直接出第一期。从第二期起自动生效。

Q：两台设备都装了，会不会重复跑？
A：会。建议只在一台设备上把定时任务设为 ACTIVE，其余设为 PAUSED 当备份；
   或者把「营销简报」目录放进同步盘，让去重历史共享。

Q：能完全不依赖电脑开机吗？
A：目前不能。定时调度是云端托管的，但执行和读写都绑定本机客户端在线。
   要彻底云端化需要同时解决三件事：云端运行环境、产出目录迁到云端存储、
   推送通道。详见 references/automation-setup.md 第四节。

Q：想改简报的口吻 / 署名 / 称呼？
A：改 SKILL.md 里的「身份与称呼」那一段。默认署名"鸭扣扣"、称呼"薇拉"。

Q：想加一个新的常看的信息源？
A：加到 references/sources.md，写清入口网址和抓取要点。下次运行就会覆盖。

Q：简报里某个源的坑想记下来？
A：写到 SKILL.md 末尾的「常见坑」里。那里已经积累了 8 条历史教训。


================================================================================
七、校验
================================================================================

装完之后，用一句"今天的营销简报"跑一次。
如果 WorkBuddy 提到了「daily-marketing-brief 技能」或开始读 references 下的
文件，说明装对了。

如果它完全没提这个技能，检查两件事：
    1. 文件夹名是不是 daily-marketing-brief
    2. SKILL.md 是不是直接在文件夹根下，而不是被多套了一层目录
