# 在新设备上复刻定时任务

本文件用于在另一台设备的 WorkBuddy 上重建「每日营销简报」定时任务。

## 一、前置条件

1. 把整个 `daily-marketing-brief/` 文件夹复制到目标设备的用户级技能目录：
   - Windows：`C:\Users\<用户名>\.workbuddy\skills\`
   - macOS / Linux：`~/.workbuddy/skills/`
2. 在该设备上确认工作目录，并建立简报存放目录 `<工作目录>/营销简报/`（首期无历史简报，跳过去重即可）。
3. （可选）用 `scripts/check_workday.py` 顶部的节假日表填入当年国务院办公厅放假安排，避免调休误判。

## 二、创建定时任务

用 `automation_update` 创建，参数：

| 字段 | 值 |
| --- | --- |
| name | 每日营销简报 |
| scheduleType | recurring |
| rrule | `FREQ=DAILY;BYHOUR=9;BYMINUTE=0` |
| status | ACTIVE |
| cwds | 该设备上的工作目录绝对路径 |

**为什么用 `FREQ=DAILY` 而不是 `BYDAY=MO,TU,WE,TH,FR`**：调休补班常落在周六 / 周日，限定工作日会漏跑；改为每日触发 + session 自行判断，周末空跑的代价只是一次判断，无产出副作用。

### 任务 prompt

```
执行「每日营销简报」：使用 daily-marketing-brief 技能，按技能中定义的流程生成本日广告营销行业资讯简报。

要求：
1. 先用 scripts/check_workday.py 判断是否触发——非中国大陆法定工作日（含调休）则不推送，直接说明原因后结束。
2. 简报目录：<工作目录>/营销简报/，文件名 每日营销简报_YYYYMMDD.md。
3. 严格按技能定义的信源清单、去重规则、三档分级与产出模板执行。
4. 产出完整 .md 文件后，按技能中的推送消息格式在对话中直接发给主人，并附上文件路径。
```

> 注：把 `<工作目录>` 替换为该设备的实际绝对路径。也可以直接在 prompt 里写死路径，避免跨设备歧义。

## 三、跨设备一致性注意事项

- **去重依赖本地历史文件**。若新设备没有历史 `营销简报/` 目录，首期不做去重，从第二期起自动生效。
- 若要多台设备共享同一份简报历史（避免两台机器各自去重、内容重复），把 `营销简报/` 放到同步盘（OneDrive / 云盘）并把 cwds 指向同步目录。
- **避免两台设备同时跑**：同一时间段两台设备都在线会各生成一份，建议只在一台设备上保持 ACTIVE，其余设为 PAUSED 作为备份。

## 四、关于"云端化"

现状：定时**调度**由平台托管，但**执行**绑定本机客户端在线——电脑关机时不执行，且读写本地 `营销简报/` 目录。

若要彻底脱离本机，需要同时解决三件事：
1. 云端运行环境（云端容器 / 常驻服务）替代本机客户端
2. 产出目录迁到云端存储（资料库 / 腾讯文档），否则去重与存档仍依赖本地文件
3. 推送通道（微信直发目前无可用连接器；退化为在对话中给出可复制的文字版）

这是三个独立改造项，不要混为一谈。维持现状 + 单台常开设备是最低成本方案。
